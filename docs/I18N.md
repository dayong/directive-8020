# Directive 8020 国际化实施记录

目前完成九语言共享 UI，以及首页、人物总览、奖杯与成就、操作设置、流程导航、选择与回退规则、多人模式、购买、收集品、时长规划、演员、PC 故障排查、隐私政策十三类页面，并增加十位船员的九语言详情，按官方资料纠正明确错误。未声称九种语言的所有攻略正文已完成，也未声称整站所有旧攻略事实均已核实。

## 技术方案

- 项目为 Next.js 14.2.35、React 18、TypeScript、App Router。继续使用 `[locale]`、Middleware 和 `generateStaticParams`；保持静态生成，不升级框架、不新增运行时依赖。
- 安装包没有 `node_modules/next/dist/docs/`，实施前查阅了对应版本官方文档：https://nextjs.org/docs/14/app/building-your-application/routing/internationalization 。
- 英文公开 URL 保持无前缀，内部重写到 `/en`。`/en`、大小写变体及旧 `/zh-hant` 等别名永久重定向到规范路径。查询参数保留。
- UI 资源为 `i18n/messages/<locale>.json`，按导航、Footer、面包屑、卡片、无障碍等功能字段分组。`getUiStrings(locale)` 在服务端按需读取当前语言，并读取英语用于校验及缺失 key 回退；不会一次读取九份字典。
- 客户端通过 MessagesProvider 接收当前字典。ChoicesView 间接引用的 ChoiceCard 也使用 Context，避免将服务端文件读取或所有词典打进客户端。
- `UiStrings` 加 JSON 模块类型断言检查所有语言结构；开发环境检测缺失 key 与插值变量，生产环境提供英语缺失字段回退。
- `i18n/format.ts` 使用原生 Intl，提供数字、显式 UTC 日期、复数与变量插值。旧组件的字符串替换并未全部迁移到该工具。

## 语言切换与用户体验

- Header 使用地球图标、当前语言及原生 details／summary 折叠菜单；列表显示语言原生名称与当前语言标识。每种实际存在的同页译文输出真实 a href、hrefLang、lang；无译文项为带 aria-disabled 的文字，不生成错误链接。桌面与移动端共用。
- SSR 输出干净、可抓取的同页语言 URL；hydration 后补上当前 query／hash，点击时再次同步。使用普通锚点保留浏览器默认导航与 Ctrl／Cmd／中键打开方式，不预取九个页面。用户选择写入 localStorage.directive-locale，刷新由 URL 决定语言。
- 首次访问可显示浏览器语言建议；返回时可建议已保存语言。均需点击才导航，URL 不会被浏览器语言或存储偏好强制覆盖。
- 建议可以关闭；禁用存储时的读取／写入异常被捕获。
- Header 完整导航在 xl 以上显示；较窄屏幕使用底部导航，为较长的翻译留出空间。

## SEO

- canonical 为各语言自身 URL。
- 首页、人物总览及十一类完整页面输出 en、zh-CN、zh-TW、ja、ko、es、fr、de、pt-BR、x-default；其余页面仅输出实际存在且可索引的语言对应关系。
- Sitemap 与 head 使用相同的译文／可索引性规则。动态章节必须有本语言 MDX，不能仅凭翻译模板生成语言副本。
- 每个已发布语言有独立 title、description、OG、Twitter，HTML lang 随 URL。适用的 FAQ/VideoGame 有 inLanguage，JSON-LD 转义 `<`。
- 保留 Git 内容变更日期计算 lastModified，修正英文 MDX 文件路径；无 Git 环境不虚构更新时间。
- 公开搜索结果不能证明实际 Google 索引状态；未接入 Search Console，也未提交部署或索引请求。
